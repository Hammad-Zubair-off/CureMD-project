# Smart Healthcare Platform — Local Setup Runbook

Verified on macOS with **Colima** + **Docker Compose**. Repository path: `~/Github/smart-healthcare-platform`.

## Prerequisites

| Tool | Version used | Notes |
|------|--------------|-------|
| Colima + Docker | Docker 29.6, Compose 5.2 | Installed via Homebrew (`brew install colima docker docker-compose`) |
| Node.js | v25+ | For frontend `npm run dev` |
| Ports | 80, 5173, 3001–3004, 3006, 27017 | Free before starting |

Start Colima if needed:

```bash
colima start
export DOCKER_HOST=unix://$HOME/.colima/default/docker.sock
```

## First-time bootstrap

```bash
cd ~/Github/smart-healthcare-platform
./scripts/setup-core.sh
```

This creates:

- `services/{auth,patient,doctor,appointment,notification}-service/.env`
- Shared `JWT_SECRET`, `INTERNAL_SECRET`, local MongoDB URIs

### MongoDB (local dev default)

We use **local MongoDB in Docker** via `docker-compose.local.yml` instead of MongoDB Atlas for development:

```
mongodb://mongo:27017/<database>
```

Databases: `auth-db`, `patient_db`, `doctor-db`, `appointment-db`, `notification-db`

To switch to **MongoDB Atlas**, replace `MONGODB_URI` in each service `.env` with Atlas connection strings and keep `JWT_SECRET` identical across all services.

### Secrets checklist (core services)

| Variable | Services | Value (local dev) |
|----------|----------|-------------------|
| `JWT_SECRET` | All 5 core | Same random hex (auto-generated by setup) |
| `INTERNAL_SECRET` | appointment | Auto-generated |
| `MONGODB_URI` | All 5 | `mongodb://mongo:27017/<db>` |
| `BREVO_API_KEY` | notification | Placeholder (service starts; email sends fail until real key) |
| `CLOUDINARY_*` | patient | `localdev` placeholders (uploads fail until real keys) |

## Daily start

**Terminal 1 — backend:**

```bash
cd ~/Github/smart-healthcare-platform
./scripts/start-core.sh
```

**Terminal 2 — frontend:**

```bash
cd ~/Github/smart-healthcare-platform/frontend
npm run dev
```

Open **http://localhost:5173**. Vite proxies `/api/*` → `http://localhost:80` (nginx gateway).

## Known issues & fixes

1. **nginx restart loop on partial profiles** — Fixed by `nginx.local.conf` + `docker-compose.local.yml` overlay (Docker embedded DNS resolver).

2. **`.env.example` incomplete** — `setup-core.sh` appends `INTERNAL_SECRET`, Brevo, Cloudinary vars.

3. **Local events use direct HTTP** — Local dev sends events by **direct HTTP** POST between services (no `QSTASH_TOKEN` set). Upstash QStash is prod-only.

4. **Doctor accounts need approval** — New doctors have `isApproved: false`. For dev, approve via MongoDB:
   ```bash
   docker exec healthcare-mongo mongosh auth-db --eval \
     "db.users.updateOne({email:'doctor@example.com'}, {\$set:{isApproved:true}})"
   ```
   Then re-login to refresh JWT.

5. **Appointments list default tab** — `GET /api/appointments/my` defaults to `tab=upcoming` (confirmed only). Pending bookings appear under `?tab=unpaid`.

6. **Port 5173 in use** — Vite falls back to 5174. Free the port or set `FE_PORT=5174` when running `test-frontend-proxy.sh`.

7. **Deferred services** — Payment, telemedicine, and AI are not started by `start-core.sh`. Use their Docker profiles when you add API keys later.
